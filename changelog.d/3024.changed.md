- Hover and press reach every widget's painter through one channel
  (#3024). `Primitive::paint` is now `paint(&self, layout, surface, env:
  &PaintEnv)`, and `PaintEnv` (`#[non_exhaustive]`, built with
  `PaintEnv::new(theme, style)` plus `with_state`/`with_interaction`)
  carries the theme, style and the resolved `InteractionState`, read with
  `hovered`/`pressed`/`hovered_sub`/`pressed_sub`/`is_hovered`/
  `is_pressed`/`child_interaction`. `InteractionState` is keyed by widget
  plus sub-part (`from_targets`, `hovered_target`, `track_painted`), and
  every runner feeds pointer events into a per-thread ambient state
  (`interaction::track_pointer`, `ambient_interaction`,
  `reset_ambient_interaction`). `draw_dyn(.., &())` paints with the
  ambient state; pass an `InteractionState` as the state to pin hover.
  StatusBar, Toolbar, SidebarPanel header, ActivityBar, MenuBar,
  ContextMenu (and MenuSystem dropdowns), Palette rows, Button, Switch,
  RadioGroup and TabBar now tint from it on pixels and cells alike, with
  menu, palette and tab rows gaining hover/press tints on cells. The
  Palette create row has its own sub-part, `Palette::CREATE_ROW`, so
  hovering an item no longer tints it. On macOS, pointer moves and
  releases now go through the shared event pre-processing like every
  other backend, so hover tracks and a press releases there too. The
  binding-core toolbar chrome paints through `draw_dyn`, so its buttons
  are hit-tested by the same ambient state.
