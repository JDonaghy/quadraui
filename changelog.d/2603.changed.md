- `TreeView`'s GTK/macOS/Windows `native_surface_paint::paint`/
  `paint_with_scroll_px` and TUI `draw_tree`/`draw_tree_with_scroll_px` now
  paint a row's leading indent + disclosure chevron + icon through a
  shared `pub(crate) fn paint_tree_cell` helper (one per backend
  family) instead of each repeating the same cursor/column
  arithmetic inline (#2603). The pixel-backend helper returns the painted
  chevron's hit-testable bounds and the rect left over for the caller's
  own label/badge text; the TUI helper returns the equivalent column
  range. `layout_metrics::tree_layout_inner` (pixel hit-testing) and
  `tui::tree::tui_tree_layout_with_scroll_px` (TUI hit-testing) now call
  the same chevron-boundary formula (`tree::chevron_end_x` /
  `tui::tree::chevron_glyph_end`) the painters use, instead of each
  re-deriving it. Pure refactor — no behavior change; every existing
  `TreeView` test, including inline-rename (`TreeRowEditState`) and badge
  painting, stays green.
