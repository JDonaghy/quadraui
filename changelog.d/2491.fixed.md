- `FindReplacePanel`'s shared `native_surface_paint::paint` now sizes every
  input/toggle/nav/action box at `Style::control_height` (26px) instead of
  the backend's raw chrome line height, and insets the popup's content from
  its border by `Style::padding` (8px) instead of one ad hoc char
  cell/line (#2491): the find/replace overlay's inputs and icon toggle
  buttons on a GUI pixel backend (GTK/macOS/Win) now match the 26px
  "standard single-line control" height `Button`/`TextInput` already
  resolve from the same token, with their text/cursor/selection highlight
  re-centered within the taller box. TUI (cell-quantised, no sub-cell
  height to refine) is unaffected — `compute_hit_regions`'s char-cell
  layout contract, which TUI shares, is unchanged. A new `FindReplaceMetrics::resolve`
  exposes this geometry so `FindReplacePanel::hit_test` callers can feed it
  the same `content_origin`/row pitch `paint` itself resolves, instead of
  re-deriving (and drifting from) that arithmetic on their own.
