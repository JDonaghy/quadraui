- **Breaking:** all 15 `Backend` tab-bar methods are removed (#2986) —
  `draw_tab_bar`, `draw_tab_bar_with_state`, `draw_tab_bar_layout`,
  `draw_tab_bar_layout_with_state`, `draw_tab_bar_icons`,
  `draw_tab_bar_icons_layout`, `draw_tab_bar_with_chrome`,
  `draw_tab_bar_with_chrome_layout`, `draw_tab_bar_with_chrome_and_glyphs`,
  `tab_bar_layout`, `tab_bar_layout_icons`, `tab_bar_layout_with_chrome`,
  `resolve_tab_bar_layout`, `resolve_tab_bar_layout_icons` and
  `resolve_tab_bar_layout_with_chrome`. Paint a tab strip by pushing the
  `TabBar` descriptor through `DrawsPrimitives::draw_dyn` /
  `draw_primitive` (or `Surface::Widget`), read its geometry back off the
  returned `TabBarPrimitiveLayout::layout`, and use
  `DrawsPrimitives::layout_primitive` for the no-paint query. What the
  removed methods took as sidecar arguments now lives on the descriptor:
  `chrome` -> `TabBar::chrome`, `icons` -> `TabBar::icons`, `glyphs` ->
  `TabBar::glyphs`. `backend::tab_bar_hits_from_layout` +
  `backend::shift_tab_bar_hits` convert a resolved `TabBarLayout` into the
  legacy `TabBarHits` shape for a caller that still reads
  `slot_positions` / `close_bounds` / `correct_scroll_offset`.
  `hovered_close_tab` / `hovered_tab` / `pressed_tab` have no replacement
  on the widget contract: `Primitive::paint` takes no paint-time state, so
  a hover or press tint is not expressible through `draw_dyn` yet.
- **Breaking:** the four per-backend tab-bar rasteriser modules are
  removed with them (#2986) — `quadraui::tui::{draw_tab_bar,
  draw_tab_bar_icons, draw_tab_bar_icons_with_chrome,
  draw_tab_bar_icons_with_chrome_and_glyphs, draw_tab_bar_with_chrome,
  tui_tab_bar_layout}`, `quadraui::gtk::{draw_tab_bar, draw_tab_bar_icons,
  draw_tab_bar_icons_with_chrome,
  draw_tab_bar_icons_with_chrome_and_glyphs, draw_tab_bar_with_chrome,
  draw_tab_bar_with_chrome_and_glyphs}`, `quadraui::macos::tab_bar` (and
  its `draw_tab_bar` / `mac_tab_bar_pixel_layout` re-exports), and
  `quadraui::win::{draw_tab_bar, draw_tab_bar_icons,
  draw_tab_bar_layout, draw_tab_bar_icons_layout, win_tab_bar_layout,
  win_tab_bar_layout_icons, win_tab_bar_native_layout,
  win_tab_bar_native_layout_icons}`. Windows no longer carries its own
  DirectWrite `pixel_layout` or Direct2D paint loop: it measures through
  `layout_metrics::pixel_tab_bar_layout_fitting_boundary` and paints
  through `primitives::tab_bar::native_surface_paint`, the same shared
  layout and painter GTK and macOS already used, so the Win strip picks up
  the rounded active-tab chip, the 1 px chip-edge accent, the alpha-blended
  close-hover backdrop, italic preview labels and `TabFrame::Brackets`
  framing it previously painted differently or not at all.
- `quadraui::tui::tab_bar`, `quadraui::gtk::tab_bar`,
  `quadraui::macos::tab_bar` and `quadraui::win::tab_bar` no longer exist
  as modules; `primitives::tab_bar::cell_paint::paint` and
  `primitives::tab_bar::native_surface_paint::paint` are the only tab-bar
  painters left (#2986).
- `primitives::tab_bar::tab_part_center(bar, part)` drops its third
  `legacy: Option<(Rect, &TabBarLayout)>` parameter (#2986): with no
  per-backend rasteriser left to fill a layout cache, it resolves against
  the painted-layout record alone.
