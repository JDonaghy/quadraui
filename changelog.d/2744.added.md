- Windowed `list`/`tree`/`data_table`/`text_display` leaves now honour their
  `items_window` in layout, paint and scrolling (#2744). A leaf whose render
  callback sends `{"items_window": {"start": ..., "total": ...}}` alongside a
  slice of its rows now paints a scrollbar extent for the whole collection
  (`PaintedHit::List::total_items`, `::Tree::total_rows`, `::DataTable::total_rows`,
  `::TextDisplay::total_lines`), scrolls by absolute row index across the full
  extent (wheel, scrollbar drag, `Home`/`End`/arrow/page keys), and paints empty
  placeholders at positions the app has not supplied yet. Only the band of rows
  the viewport actually shows is materialised per frame, so a 100,000-row window
  costs the same per frame as a 50-row one and an adversarial `"total"` can never
  drive an unbounded allocation.
- `RowsRequested` is now emitted end to end (#2744): once a scroll input moves a
  windowed leaf's viewport outside the loaded slice, `InteractionEngine::handle`
  computes the bounded `{id, start, count}` request and delivers it through the
  new `EventSink::dispatch_rows_requested` (a default method, so every existing
  `EventSink` impl keeps compiling). `quadraui-py` and `quadraui-node` surface it
  to the registered handler as `{"RowsRequested": {id, start, count}}`; an app
  answers by re-rendering that leaf with an `items_window` starting at `start`,
  and a slice already loaded is never re-requested.
- New in `quadraui-binding-core`: `render::paint_layout_windowed`/`paint_leaf_windowed`,
  `host::resolve_layout_node_windowed`, `host::apply_tree_nav_key_windowed`/
  `resolve_tree_cursor_windowed` (a windowed tree's cursor is tracked by absolute
  index, since a not-yet-loaded row has no stable `TreePath`),
  `hit::LoadedRows`/`loaded_row_path`/`windowed_leaf_extent`, and
  `render::WindowedTreeExtent`. Every one has an unwindowed counterpart that
  behaves exactly as before, so a binding that never decodes an `items_window`
  is unaffected.
