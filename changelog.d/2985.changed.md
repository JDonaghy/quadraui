- `TabGroupController` paints each pane's tab strip through the `TabBar`
  primitive (`DrawsPrimitives::draw_dyn`) instead of
  `Backend::draw_tab_bar`, and classifies every strip click with the
  painted `TabBarLayout`'s own `hit_test` instead of comparing cached
  `TabBarHits` x-ranges by hand (#2985). `render` still returns the same
  `TabGroupLayout`, `handle_click_event`/`handle_tab_drag_start`/
  `drop_group_rects` still report the same events and geometry, and
  `set_drag_geometry` still primes drag hit-testing without a render
  pass. `PaneDragRect::tab_slots` keeps its `(0.0, 0.0)` scrolled-off
  sentinel convention. `Pane::tab_scroll_offset` is now written from the
  new `TabBarPrimitiveLayout::corrected_scroll_offset` rather than
  `TabBarLayout::resolved_scroll_offset` (which is only clamped, not
  corrected), so a GTK pane with more tabs than fit the strip keeps the
  active tab in view across frames instead of pinning to offset 0.
- `TabBar`'s widget contract — its `Primitive` and `Interactive` impls,
  `TabBarPrimitiveLayout`, `TabBarState`, and `WidgetAction for
  TabBarEvent` — now compiles with no backend feature enabled, matching
  `CellGrid` (#2985). The impls were already backend-agnostic (their
  TUI-specific branches carry their own `tui` gate), and dropping the
  outer gate is what lets a backend-generic `AppLogic` push a `TabBar`
  through `Surface::Widget` in a feature-free type-check such as
  `cargo check --test acceptance`.
- Every remaining `Backend` tab-bar caller stays on its `Backend` method
  until slice 1 of the TabBar port (#2984) lands the two seam
  deliverables its own body names and its own merge left open — #2984 is
  still open, marked `ISSUE_RESOLUTION: partial`, for exactly these two
  (#2985). Both are pinned by tests in `tests/cross_backend_parity.rs`,
  which fail the day either one closes:
  - **One shared pixel layout built on `LayoutCtx::measure`** (#2984's
    wording). `LayoutCtx` carries `char_width` and no text measurer, so
    `TabBar`'s `Primitive::layout` approximates every glyph at one
    `char_width`, while a pixel rasteriser feeds `pixel_tab_bar_layout`
    real font widths (GTK Pango measures `alpha`/`beta`/`gamma` at
    36/29/50 px where the approximation gives 45/36/45 at `char_width:
    9`). The error runs in both directions, so no scalar correction
    closes it, and the resulting strip differs visibly — a 200 px
    sidebar strip ellipsises `gamma` to `gam…` where the rasteriser fits
    it. Closing it means a text measurer on `LayoutCtx` — a public,
    non-`#[non_exhaustive]`, `Copy`/`PartialEq`-deriving struct built by
    literal at 60 sites in this repo plus `quadraui-binding-core`'s
    script-widget seam — which is slice 1's seam work, not slice 2's
    caller migration.
  - **`TabChrome`, glyphs and icons as descriptor fields** (#2984's
    wording). `TabBar` carries neither a `TabChrome` nor a `TabIcon`
    field, and `Primitive::paint` takes no paint-time state
    (`DynWidget::paint`'s `&dyn PaintState` is dropped by the blanket
    impl, and `PaintState`'s accessors cannot carry a sidecar anyway),
    so there is no route for one through the contract. A required-field
    add to `TabBar` also breaks the sealed oracle's own struct literals
    (`tests/acceptance/ms-11/c0_paint_smoke.rs`,
    `tests/acceptance/ms-11/wide_tab_labels.rs`), which is why #2984
    reports it as needing an operator/test-author sealed-oracle update
    in the same PR.
  Callers still on a `Backend` tab-bar method, and which deliverable
  each waits on: the measurer blocks `compose::workspace`,
  `compose::bottom_panel`, `quadraui-gallery`'s main-pane strip,
  `quadraui-binding-core`'s `tab_bar` slot and `LeafDescriptor::TabBar`
  leaf, and `examples/common/demo.rs`; the descriptor fields block
  `quadraui-gallery`'s chrome and icon variants, `tab_chrome_demo`,
  `tab_icons_demo`, and `quadraui-binding-core`'s `"tabs"` layout node,
  which requests a focused-tab `TabChrome`. Removing
  `quadraui-binding-core`'s per-kind tab-bar code — the `RenderRefs`
  `tab_bar` slot, `host.rs`'s `SLOT_TAB_BAR` arms and `semantic.rs`'s
  per-kind routing — is gated on the same two, because every one of
  those paths paints through a `Backend` tab-bar method today.
