- `TabGroupController` paints each pane's tab strip through the `TabBar`
  primitive (`DrawsPrimitives::draw_dyn`) instead of
  `Backend::draw_tab_bar`, and classifies every strip click with the
  painted `TabBarLayout`'s own `hit_test` instead of comparing cached
  `TabBarHits` x-ranges by hand (#2985). `render` still returns the same
  `TabGroupLayout`, `handle_click_event`/`handle_tab_drag_start`/
  `drop_group_rects` still report the same events and geometry, and
  `set_drag_geometry` still primes drag hit-testing without a render
  pass. `PaneDragRect::tab_slots` keeps its `(0.0, 0.0)` scrolled-off
  sentinel convention. `Pane::tab_scroll_offset` is now written from the
  new `TabBarPrimitiveLayout::corrected_scroll_offset` rather than
  `TabBarLayout::resolved_scroll_offset` (which is only clamped, not
  corrected), so a GTK pane with more tabs than fit the strip keeps the
  active tab in view across frames instead of pinning to offset 0.
- `WorkspaceController` and `BottomPanelController` paint their tab
  strips through the same `TabBar` widget contract and classify strip
  clicks with the painted `TabBarLayout`'s own `hit_test`, instead of
  caching `TabBarHits` x-ranges from `Backend::draw_tab_bar` (#2985).
  Both still report the same events for the same clicks — close glyph
  before tab body, `WorkspaceController`'s middle-click still closes
  anywhere on a tab's full span, `BottomPanelController`'s maximise
  segment still toggles — and `WorkspaceController::render` keeps its
  two-pass paint, now driven by
  `TabBarPrimitiveLayout::corrected_scroll_offset`.
- `TabBar`'s widget contract — its `Primitive` and `Interactive` impls,
  `TabBarPrimitiveLayout`, `TabBarState`, and `WidgetAction for
  TabBarEvent` — now compiles with no backend feature enabled, matching
  `CellGrid` (#2985). The impls were already backend-agnostic (their
  TUI-specific branches carry their own `tui` gate), and dropping the
  outer gate is what lets a backend-generic `AppLogic` push a `TabBar`
  through `Surface::Widget` in a feature-free type-check such as
  `cargo check --test acceptance`.
- `quadraui-binding-core` paints all three of its tab-bar paths — the
  fixed `"tab_bar"` render slot, the `LeafDescriptor::TabBar` leaf, and the
  `"tabs"` layout node — through the `TabBar` widget contract instead of a
  `Backend` tab-bar method (#2985). The `"tabs"` node's focused tab now
  reaches the paint as the bar's own `TabBar::chrome` field. `PaintedHit::TabBar`
  carries the same bar-relative `TabBarLayout`, so hit detail, key routing and
  right-segment lookup are unchanged.
- `quadraui-gallery`'s chrome and icon `TabBar` variants, `tab_chrome_demo`
  and `tab_icons_demo` set `TabBar::chrome` / `TabBar::icons` on the
  descriptor and paint through the widget contract, hit-testing clicks with
  `DrawsPrimitives::layout_primitive` instead of
  `Backend::tab_bar_layout_with_chrome` / `tab_bar_layout_icons` (#2985).
  Every pixel caller now sizes tabs with real font measurement
  (`LayoutCtx::text_width`), so a widget-contract strip lays out the same
  tabs at the same spans as the backend's own rasteriser. No in-repo caller
  outside the backends calls a `Backend` tab-bar method any more.
- `quadraui-binding-core` keeps its fixed `"tab_bar"` render slot, its
  `SLOT_TAB_BAR` host arms and its per-kind key/click routing, alongside the
  five other fixed slots (`"button"`, `"text_display"`, `"list"`, `"tree"`,
  `"data_table"`), so the flat wire shape every binding decodes is unchanged
  (#2985). The slot is what records `PaintedHit::TabBar` with the resolved
  `TabBarLayout`, so a binding's click still resolves to a tab index or a
  close glyph; the generic `widgets` map records `PaintedHit::Widget` with a
  painted area and no sub-region detail, so folding the slot in waits on a
  hit seam for `DynWidget` — the binding-core slot collapse (#2977).
