- `SidebarPanelBody` implements `Primitive` and is `non_interactive`
  (#2953). `render`/`render_with` paint the panel through `draw_dyn`: the
  background and header/search chrome no longer go through
  `Backend::draw_solid_fill`/`Backend::draw_settings_chrome`, and the
  `Search`/`StatusBars` rows paint through `StatusBar`'s own `Primitive`
  inside the panel, so they are no longer separate entries in the
  painted-widget record. Chrome rows stay pitched at the backend's chrome
  line height. New `SidebarPanelBodyPrimitiveLayout`.
- Sidebar form sections handle every press through the form's own
  handling (#2953): number-input steppers step, a slider track press
  sets the value and drags it, where the sidebar used to report only a
  focus change.
- A sidebar tree section can request a context menu for a right-click
  on its empty space (`SidebarSystem::set_empty_space_context_menu`),
  reported with an empty `path`.
- Sidebar tree rows lay out through `TreeView`'s own layout, so on a
  terminal a click on a branch row's title selects it; only the chevron
  cells before the title expand it. Selection-mode navigation keys go
  to the tree's own handling; every other key still reaches the app.
