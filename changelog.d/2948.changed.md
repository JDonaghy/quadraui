- **Breaking:** `TreeTableHit` is `{ Chevron(usize), Table(DataTableHit) }`
  (#2948), so a tree table resolves every zone a `DataTable` does.
  `TreeTableEvent::HeaderClicked` became `SortChanged { col, ascending }`:
  a header click reports the sort it asks for (ascending unless already
  sorted ascending by that column). `TreeTable` gains a `vim_keys` field
  (serde default `false`; `TreeTable::new(table, tree)` builds one) and
  `TreeTableNode` gains `children_pending` and `placeholder`.
- **Breaking:** `TreeTableController`, `TreeTableControllerEvent` and
  `TreeTableNodeData` exist only with a backend feature enabled: the
  controller drives `TreeTable`'s `Interactive` impl, which needs one.
  The controller keeps its public API.
- `TreeTable` rows carry their tree level, sibling position and expand
  state to assistive technology (#2948); the cells stay row children.
- `TreeTable` honours `DataTable::striped` (and a caller's striped paint
  state) on every backend; tree rows used to paint unstriped (#2948).
- A tree table's chevron hit bounds are clipped to column 0 on pixel
  backends too, not only on cells (#2948).
