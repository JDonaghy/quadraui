- Binding-core's completions and rich-text-popup overlays (#2978) route
  pointer input through `Completions`'/`RichTextPopup`'s own
  `Interactive::handle` instead of a hand-written hit test: a click on a
  completion row moves the highlight and a double-click accepts it, a
  wheel over an overflowing rich-text popup scrolls the popup, and neither
  overlay takes focus from the widget it floats over.
- Binding-core's `ScriptedPrimitive<W>` (#2978) implements
  `Primitive` + `Interactive` and decodes as a generic widget leaf:
  `"scripted_widget"` is a kind binding-core registers in core's runtime
  kind registry, its payload carries the registered widget's `id`, and
  `register_scripted_widget(primitive)` registers a `ScriptedPrimitive`
  under its own id. A press on a declared region reaches the script and
  the app (`UiEvent::Canvas`) through the generic widget routing; a
  focused key reaches the script and still travels on to the app.
- One per-widget state store (#2978): `quadraui::WidgetStateStore` gains
  typed host values (`resolve`/`value`/`set`) and a frame sweep
  (`mark_seen`/`keep_alive`/`gc`) and `take`/`insert`; the new
  `quadraui::lend_widget_state(id, state, f)` lends a host-held state to
  the runtime's per-thread store while `f` paints, then hands it back and
  restores whatever the store held for `id`. Binding-core's
  engine keeps every generic widget's state and every host-resolved
  value in it; `InteractionEngine::widget_state()` returns
  `&RefCell<WidgetStateStore>` and the `crate::host` `apply_*`/`resolve_*`
  helpers take that.
- Binding-core's message and form dialogs, completions list and rich-text
  popup (#2978) are one overlay-stack entry kind holding a generic
  widget: each paints through `draw_dyn` with its stored state and is
  routed through its own `Interactive::handle` (a modal dialog with
  every part focused, which claims every pointer, key and text input so
  none reaches the widget beside or beneath it), with raw input
  translated by the now-public `quadraui::compose::routed_event`.
- The binding-core engine asks every generic widget it dispatched an input
  to for `Interactive::data_requested` against a layout re-taken after
  `handle`, and activates its own widget-state store before laying a widget
  out (#2978). This replaces the `CellGrid`-only `CellsRequested` check and
  its downcast; a generic `list`/`tree`/`data_table`/`text_display` leaf
  with an `items_window` emits `RowsRequested` the same way.
- `FormDialog` (#2978) lays its form out as a `ScrolledForm`:
  `FormDialogLayout::form` is a `ScrolledFormLayout`, which carries the
  scrollbar (the `scrollbar` and `line_height` fields are gone). A Tab
  from the last field onto the first button, between buttons, or from
  the first button back onto the last field is left to the host's
  child-stop walk; the dialog keeps only its two wraps (past the last
  button, and back past the first field). `FormDialogState` and
  `FormState` are no longer `Eq`, since `FormState` holds a thumb drag.
