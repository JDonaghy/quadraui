- `quadraui::register_widget_kind(kind, decode)`/`unregister_widget_kind`
  (#2978): a widget defined outside this crate registers a runtime kind,
  and `decode_widget`/`decode_widget_from` decode it after finding no
  static `widget_kinds!` entry. Registering a kind that already exists is
  `KindError::Duplicate`. `widget_kind_names()` lists every accepted kind,
  static then runtime, and `DecodeFn` names the decoder signature,
  `fn(kind, value)`: the decoder receives the kind it decodes, so one
  function can serve every kind a scripting host defines. A
  `widget_kinds!` invocation also generates `is_static_widget_kind` and
  `static_widget_kinds`. `"command_line"`, `"number_input"`,
  `"combo_box"` and `"date_picker"` join the static table.
- `quadraui-binding-core` (#2978) gives a third binding everything it
  needs without py/node code: `register_widget_kind`/
  `register_widget_kind_with_schema` wrap the core registry and refuse a
  name a layout node already uses (a container key, a fixed leaf or extra
  kind, a sibling key such as `"style"`), which decoding would otherwise
  shadow silently; `decode_overlay(what, kind, descriptor, anchor)` turns a
  `show_overlay` call into the `DeferredAction` that opens it plus its
  dismiss id, `overlay_anchor_from_value` reads an object-shaped anchor,
  and the context-menu and message-dialog descriptor shapes are
  `wire_schema()` roots.
- `TreeTableModel` (#2978), the wire kind `"tree_table_controller"` as a
  contract widget: a hierarchical node tree the app sends as content
  every frame, lazily loaded children included, flattened and driven
  through `TreeTableController`'s own behaviour. The user's expand,
  selection, scroll and header-sort state is the widget's
  `Interactive::State` (`TreeTableModelState`); a changed `selected_id`
  selects that node, and `sort_override` tells the widget the app sends
  `nodes` in its own order. It reports `UiEvent::TreeTableModel(id,
  TreeTableModelEvent)`, serialized as `{"TreeTableController": [id,
  event]}`. `TreeTableNodeData` derives `Serialize`/`Deserialize`
  (`{"id", "cells", "icon", "has_children", "children"}`).
- `quadraui-binding-core`'s engine keeps a generic widget leaf's
  `Interactive::State` in the thread's runtime `WidgetStateStore` (#2978),
  so a widget lays out and paints with the state its own events left
  (`PaintEnv::widget_state`), the same as under the Rust runtime. Each
  engine's states stay its own: an engine puts them in the store when it
  is built and whenever it routes an event or records a frame, setting any
  other engine's aside, and dropping an engine drops them.
