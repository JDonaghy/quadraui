- `SidebarPanel` is on the widget contract (#2827): it implements `Primitive`
  and `Interactive`, reaches a frame as `Surface::Widget`, and decodes through
  `widget_kinds!` as `"sidebar_panel"`. `Primitive::layout` resolves a
  `SidebarPanelLayout` whose panel/header/content rects are absolute and
  whose `toolbar` field is the header's own `ToolbarPrimitiveLayout`
  (header-local item bounds, replacing the old absolute `toolbar_layout`);
  the default header height is one cell on a cell grid and
  `Style::toolbar_height` (floored at the row height) on a pixel surface.
  `Interactive` is pointer-only (`FocusSpec::None`): hover, press and click on
  a header button go through the header `Toolbar`'s own `Interactive` impl
  and arrive as `UiEvent::Toolbar(toolbar_id, ..)`, and an assistive-technology
  `Click` activates the first enabled header button. Breaking:
  `Backend::draw_sidebar_panel_interactive`/`Backend::sidebar_panel_layout`,
  `Surface::SidebarPanel`, `FrameZone::SidebarPanel` (a captured panel now
  reports `FrameZone::Widget`), the inherent `SidebarPanel::layout` and
  `SidebarPanelMeasure`, the `tui`/`gtk`/`macos`/`win` `sidebar_panel`
  rasteriser modules (`draw_sidebar_panel`, `tui_sidebar_panel_layout`,
  `gtk_sidebar_panel_layout`, `mac_sidebar_panel_layout`,
  `win_sidebar_panel_layout`) are removed — paint with
  `DrawsPrimitives::draw_dyn`/`draw_primitive` and hit-test with
  `layout_primitive`. A `SidebarPanel` is no longer a `ScreenLayout` tab stop.
  In `quadraui-binding-core`, the `"sidebar_panel"` layout node's header is
  recorded as a generic `PaintedHit::Widget`, so `PaintedHit::SidebarPanel`
  and the `sidebar_panel_toolbar_button` hit-detail kind are removed from the
  wire; a header-button click still emits the same `Toolbar` event.
- `CommandCenter` is on the widget contract (#2827): it implements
  `Primitive` + `Interactive`, reaches a frame as `Surface::Widget`, and
  decodes as the `"command_center"` `widget_kinds!` kind (the py/node kind
  name is unchanged). `Backend::draw_command_center` /
  `Backend::command_center_layout`, `Surface::CommandCenter`,
  `FrameZone::CommandCenter` and the per-backend `tui`/`gtk`/`macos`/`win`
  `command_center` rasteriser files (with their `#[doc(hidden)]`
  `draw_command_center` / `*_command_center_layout` re-exports) are removed;
  paint through `DrawsPrimitives::draw_dyn` and resolve geometry with
  `DrawsPrimitives::layout_primitive`. A left press on the back arrow,
  forward arrow or search box, `Enter`/`Space` on the focused strip, or an
  assistive-technology `Click` now emits the new
  `UiEvent::CommandCenterActivated { widget, target: CommandCenterTarget }`;
  a press on a disabled arrow is swallowed and one on the bar's padding
  bubbles as a plain `MouseDown`. GTK and Windows now paint the shared
  VS Code-style search box (`primitives::command_center::native_surface_paint`)
  that macOS already used, and on Windows the strip's arrows and search box
  read as client area in a custom title bar through the frame's painted
  sub-regions rather than per-part `register_zone` entries.
  `OwnedContent::CommandCenter` stays as the widget's capture and maps to
  `FrameZone::Widget`.
- `DropOverlay` is a widget-contract primitive (#2827): it implements
  `Primitive` (layout and measure from `DropOverlay::bounds`, the shared
  pixel painter on GTK/macOS/Windows and a cell painter on TUI) and is
  `non_interactive!`. A host paints it with `DrawsPrimitives::draw_dyn` at
  `DropOverlay::bounds()`, or pushes it as a `Surface::Widget` at that
  rect, and registers the new `DROP_OVERLAY_ZONE_ID` zone there to
  attribute the text-free overlay in a frame's inventory.
  `TabGroupController::render` does both while a tab drag is active.
  `Backend::draw_drop_overlay`, `Surface::DropOverlay`,
  `OwnedContent::DropOverlay` and `FrameZone::DropOverlay` are removed,
  along with the per-backend `drop_overlay` rasteriser files.
  `DropOverlay::bounds` now covers both the highlight and the insertion
  bar (widened to `DropOverlay::MIN_BAR_THICKNESS`) rather than whichever
  one is present first, so a pixel backend's clip to that rect never cuts
  the bar off. `OwnedFrame::from_layout` fills `OwnedNode::a11y` from a
  `Surface::Widget`'s own `A11yPrimitive` impl when its content captures
  as `OwnedContent::Opaque`, so a drop overlay still reads as a
  `presentation "Drop overlay"` node.
