- `Backend::focus_tree`/`focus_tree_mut` (#2909): read/write access to this
  backend's `focus::FocusTree`, alongside (not yet replacing)
  `Backend::focus_manager`/`set_focus`. `set_focus` keeps both in step for
  every whole-widget focus change, so no existing caller needs to change.
  `runtime::route_widget_key` and the widget-contract routing engine's
  `EventHost` now read this tree instead of the flat `FocusManager`, so a
  composite widget's `EventHost::is_focused`/`request_focus` can finally
  tell its own children apart by `SubTarget` instead of answering every
  child identically for one focused id. `AppLogic::extra_tab_stops` is a
  new, empty-by-default hook alongside the existing `AppLogic::tab_stops`
  (the shared runner reads and cycles both, concatenated) for an app that
  wants a second source of Tab stops without touching its existing
  override. `FocusTree` now derives `Debug`/`Clone`/`PartialEq`, matching
  `FocusManager`, so a backend can embed it in a struct that derives those.
  `AppLogic::tab_stops` stays un-deprecated for now: `quadraui-binding-core`/
  `quadraui-py`/`quadraui-node` all override it, and migrating those (plus
  the shared pipeline's own Tab/Shift+Tab cycling step 4, which still reads
  the `FocusManager`-shaped `tab_stops`/`extra_tab_stops` pair rather than
  `FocusTree`) is left for a follow-up issue scoped around that call-site
  count.
