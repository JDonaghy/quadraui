- `SidebarSystem` and `SidebarEvent` are removed (#2957); host the
  `Sidebar` widget directly. `Sidebar::from_defs` builds it from
  `SidebarSectionDef`s, `Sidebar::set_rows` keeps a row's rename session
  across rebuilt rows, and `start_editing`/`cancel_editing`/`is_editing`,
  `reveal`/`reveal_in` and `toggle_expand_selected` move onto the widget.
  A host that drives it with raw `UiEvent`s holds a `SidebarState` and
  calls `Sidebar::handle_event` (or `handle_event_in` with a
  `LayoutCtx`), which answers every `SidebarAction` the event produced
  for the host to `apply`; paint it with `draw_dyn`. The former
  accessors and setters are the widget's public fields (`active_section`,
  `navigation_mode`, `scroll_mode`, `panel_scroll`, `allow_collapse`,
  `has_focus`, and each `SidebarSection`'s `collapsed`, `visible`,
  `badge`, `empty_space_context_menu` and `form_focused`), with
  `tree`/`tree_mut`/`form`/`form_mut` for the bodies. The
  `compose::sidebar_system` module is now `compose::sidebar`.
