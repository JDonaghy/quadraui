- macOS `ToolbarOverflow::Wrap`/`ToolbarOverflow::Menu` rasteriser (#2639):
  `MacBackend::draw_toolbar_with_overflow` / `toolbar_layout_with_overflow`
  now override the shared defaults, backed by new
  `macos::toolbar::mac_toolbar_layout_with_overflow` /
  `draw_toolbar_with_overflow` free functions — `Wrap` stacks overflowing
  rows below the bar, clipped to the slot the caller allocated, instead
  of clipping to a single row, and `Menu` paints the trailing `[ » ]`
  affordance (a click hit-tests to `ToolbarHit::Overflow`;
  `examples/common/toolbar_overflow_demo.rs` now opens the dropped items
  as a native `NSMenu` via `Backend::show_context_menu` wherever a
  backend implements it). The shared `native_surface_paint::paint` the
  GTK/macOS rasterisers both use now resolves `ToolbarItemKind::Overflow`'s
  synthetic `»` button and fills the full area every visible item's
  bounds span rather than just the caller's original single-row rect, so
  a `Wrap` layout's extra rows get the bar's background too. Demoed in
  `examples/macos_toolbar_overflow.rs`.
