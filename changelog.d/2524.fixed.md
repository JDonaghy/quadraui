- GTK `Backend::request_frame_in` no longer panics ("default main context
  already acquired by another thread") when the default `glib::MainContext`
  is owned by a thread other than the caller's (#2524): it arms no timer in
  that state instead of letting `glib::source::timeout_add_local_once`
  abort. A test process that runs `gtk4::init()` from a harness-spawned
  thread stays in that state permanently, which made every headless
  `gtk::testing::GtkDriver` test whose app returns
  `Reaction::RedrawAfter` panic on a host with a display.
