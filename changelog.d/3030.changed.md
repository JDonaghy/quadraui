- The contract `Editor` resolves clicks, carets and selections against the
  glyphs it actually painted (#3030). `EditorLayout::col_at_x` and
  `EditorLayout::x_at_col` take a new `Option<&mut dyn PaintSurface>`
  argument (pass `backend.paint_surface()`) and measure the row through
  that surface's editor-font text verbs with the row's bold, italic and
  scale runs applied — Pango on GTK, Core Text on macOS, DirectWrite on
  Windows — so proportional fonts and wide glyphs (emoji, CJK) land on the
  right column; a click inside a glyph resolves to that glyph's column and
  columns past the end continue one cell each. The measurement runs only
  when asked (a logarithmic number of shapings per click), never per frame.
  `EditorEvent::Pointer` (and the `EditorHit::BufferPos` it carries)
  reports that measured column through the new
  `EventHost::text_surface`/`EventCx::text_surface` hook, which the
  runtime fills with the backend's paint surface. Without a surface — the
  TUI cell grid — columns count display cells: a wide glyph takes two
  cells and a tab runs to the next tab stop. The TUI editor now paints a
  wide glyph across two cells, and `text_util::char_col_to_visual` counts
  each character's display width rather than one cell per character. GTK's
  text verbs measure outside a frame on the last painted frame's Pango
  context instead of panicking.
