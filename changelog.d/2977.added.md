- `Primitive::text_region` (#2977): a primitive reports the selectable
  text it painted, and `draw_primitive`/`draw_dyn` register it through
  `Backend::register_text_region`, so drag-select and copy work on it on
  every host. `MessageList` reports its painted transcript rows.
- `quadraui_binding_core::widget_leaf_kinds()` (#2977): the kinds a
  binding's layout leaf or flat render dict decodes as a generic widget —
  the built-in generic kinds plus every kind registered at runtime with
  `quadraui::register_widget_kind`. A runtime-registered kind now decodes,
  paints and routes through binding-core with no table edit, so a host
  binding outside py/node can add widget kinds of its own.
- `quadraui::popup::resolve_open_popups`, `route_popup_event`,
  `popup_at` and `PopupRouting` (#2977): the open-popup resolution and
  the press/release/wheel/Escape/outside-press routing rules the
  widget-contract runtime applies, public so a host that routes events to
  widgets it painted itself (binding-core) routes their popups by the same
  rules. The runtime routes its frame tree's popups through them.
- `FormState::focused_field` (#2977): the field focus a `Form` tracks
  itself while its descriptor leaves `focused_field` unset, so Tab, Up/Down
  and clicks move field focus and typing edits that field with no host
  echoing `FormEvent::FocusChanged` back.
- A core row-windowing seam (#2977): `ListView`, `TreeView`, `DataTable`
  and `TextDisplay` take `items_window: Option<ItemsWindow>` (and the
  first three `scroll_px: Option<f32>`) as real descriptor fields, with the
  same wire keys the bindings already accepted. A windowed widget lays out
  and paints only a viewport-sized band (placeholders for rows outside the
  loaded slice, scrollbar sized from the real total), moves its cursor and
  scroll by absolute index, and asks for rows with the new
  `UiEvent::RowsRequested { id, start, count }` — the wire shape
  `test_windowed_rows_requested.py` already expects — once per new range.
  `quadraui::behaviour::row_window` holds `ItemsWindow`, the band
  arithmetic, `HostLatch` and `RowsRequestLatch`; `FlatNav::mv_all`
  navigates a total too long to enumerate.
- `Interactive::data_requested` and `Interactive::state_summary` (#2977),
  defaulted hooks mirrored on `DynWidget`: the content a widget needs
  loaded after an input (a windowed collection's `RowsRequested`, a
  `CellGrid`'s `CellsRequested`), and a `StateSummary` of the selection,
  scroll, active tab and expansion it resolves. The core runtime and the
  binding-core engine ask `data_requested` after every input a widget
  handled.
- `"text_display"` is registered in `widget_kinds!`, and `TextDisplay`
  registers its own selectable `TextRegion` through
  `Primitive::text_region` (#2977).
- `Interactive::SCROLLS_OWN_ROWS` and `Interactive::scrolled_to_row`
  (#2977), mirrored on `DynWidget` as `scrolls_own_rows`/`scrolled_to_row`:
  a widget that paints a window of its content from its own scroll
  position (`ListView`, `TreeView`, `DataTable`, `TextDisplay`) says so,
  and returns a copy of itself scrolled to a given first row. A host
  scroll container holding such a widget keeps it on the viewport and
  paints that copy; binding-core's `scroll` node does, with no per-kind
  table.
- `TreeViewState::window_cursor_anchor` and `tree::WindowCursorAnchor`
  (#2977): what the descriptor and the cursor's row said when a windowed
  tree last handled input, so a new `selected_path` the app sends moves
  the cursor and a re-flattened row set keeps it on its row's path.
