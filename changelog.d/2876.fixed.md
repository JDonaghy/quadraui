- `TextDisplay` and `CommandLine` now report `FontRole::Editor` from
  `Primitive::font_role`, the role `EditorClassPrimitive::ALL` already
  listed them under (#2876): on the widget-contract paint path both were
  falling back to the trait's chrome default, so their rows were measured
  and painted in the host chrome font instead of the editor font. A
  `TextDisplay`'s rows also lay out on `LayoutCtx::editor_line_height`
  now, the same row pitch the editor-font surface it paints through
  reports, so row hit-testing and the painted rows stay on one grid when
  the two fonts differ in height.
- `TextInput` measures its monospace caret grid with the advance of the
  font it actually paints in, through `LayoutCtx::text_width` and its own
  `Primitive::font_role`, rather than the ambient `LayoutCtx::char_width`
  (#2876). `char_width` is the editor advance; an input painted in the
  chrome font put its caret on the editor pitch, so the caret drifted
  away from the glyphs beside it whenever the two fonts differed.
