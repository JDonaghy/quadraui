- `DataTable`'s GUI and TUI painters are now each split into `paint_header`/
  `paint_row`/`paint_cell` (GUI) and `draw_header`/`draw_row`/`draw_cell` (TUI)
  helpers, with `paint_row`/`draw_row` taking an optional per-column cell-paint
  hook that a future `TreeTable` can use to override column 0 while every
  other column still renders through the unchanged default cell painter
  (#2602). `DataTablePaintState` is now a type alias of the shared
  `primitives::row_stack::RowPaintState` (the same type `ListPaintState` and
  `TreePaintState` already alias) instead of its own struct; both painters'
  body-row stacking now goes through `row_stack::stack_rows_from` and their
  vertical scrollbar thumbs through `row_stack::vscrollbar_thumb`. The shared
  GUI painter's three entry points collapse into one,
  `native_surface_paint::paint_with_state` — `paint` had no callers and
  `paint_with_glyphs` is subsumed by it; `win::data_table` and
  `macos::data_table` call the single entry point directly. All of this is
  crate-internal (`pub(crate)`), with no behavior change.
