- `ToolbarOverflow` (#2637): `Clip` (today's default, unchanged), `Wrap`,
  and `Menu`, set via `ToolbarLayoutOptions::with_overflow` and consumed by
  the new `Toolbar::layout_with_overflow` (kept separate from
  `layout_with_options`, which keeps ignoring it, so Clip's own geometry
  never moves). `Wrap` flows overflowing top-level items onto additional
  lines — never splitting a `Group` — and `ToolbarLayout::cross_extent`
  reports how much cross-axis room they used, so a host can grow its
  container before the next paint. `Menu` drops top-level `Action`/`Group`
  items lowest-priority-first (new `ToolbarOverflowPriorities` side table,
  same registration shape as `ToolbarIcons`) behind a trailing `»`
  affordance — `ToolbarItemKind::Overflow`, `ToolbarHit::Overflow` (now
  `#[non_exhaustive]`) — and `ToolbarLayout::overflowed_items` converts
  what was dropped into `ContextMenuItem`s ready for a `ContextMenu`,
  recursing an exclusive `Group`'s children into radio items. TUI ships
  the full rasteriser (`tui::draw_toolbar_with_overflow` /
  `tui_toolbar_layout_with_overflow`, extra terminal rows for `Wrap`, a
  `[ » ]` cell for `Menu`) via a new defaulted
  `Backend::draw_toolbar_with_overflow` / `Backend::toolbar_layout_with_overflow`
  pair; every other backend inherits the default, which forwards to
  today's Clip-only `draw_toolbar_with_options` unchanged. Demoed in
  `examples/tui_toolbar_overflow.rs`.
