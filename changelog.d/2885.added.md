- Widget-contract routing engine (#2885): `FrameTree`/`FrameTreeNode`
  (`quadraui::frame_tree`) — the current frame's `Interactive` widgets as
  `(id, rect, widget)` nodes, built via `ScreenLayout::into_frame_tree` or
  assembled directly — and `WidgetStateStore`/`WidgetRoutingState`
  (`quadraui::widget_state`) — persistent per-widget `Interactive::State`
  plus hover/capture bookkeeping. `AppLogic::frame_tree` is a new,
  empty-by-default per-event hook (mirroring `AppLogic::tab_stops`) an app
  overrides to opt in. `runtime::preprocess_event` gained a new step
  (right after double-click folding) that hit-tests/focus-routes/captures/
  synthesizes Enter-Leave for these widgets and calls
  `Interactive::handle` directly, bubbling an unclaimed event down to the
  rest of the pipeline unchanged; an open `ModalStack` entry blocks the
  whole step. A new `a11y::route_widget_action` feeds a
  `Surface::Widget` id's assistive-technology action through the same
  `Interactive::handle` path `route_action` cannot reach (it only ever
  sees a captured `A11yTree` snapshot, never the live widget). `BackendCore`
  carries the new `WidgetRoutingState` field; `TuiBackend`'s
  `PreprocessBackend` impl is the one backend wired up today (GTK/macOS/
  Win keep the trait's `None`-returning default, zero behavior change).
