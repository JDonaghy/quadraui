- Every editable text widget undoes and redoes through one shared history
  (#2978 TE7): `behaviour::text_edit::EditHistory` serves `EditOp::Undo`/
  `EditOp::Redo` for `TextEditor`, `LinesEditState` (`TextInput`) and
  `FlatEditState` (`TextField`, `CommandLine`, the palette query,
  `PasswordInput`, `TextArea`, ...). Ctrl/Cmd+Z undoes and Ctrl/Cmd+Shift+Z
  redoes in every one of them; with nothing to give back the chord stays
  `Ignored`, so an app accelerator still fires. The history survives a
  focus change. **Breaking:** `FlatEditState` and `LinesEditState` gain a
  `history` field and are no longer `Copy`, and neither are
  `DualModePaletteState` and `PathPickerEditState`, which hold one.
- **Breaking:** `form::TextCursor` gains a `history: EditHistory` field so
  a `Form` text row keeps its undo history while it holds focus; code that
  builds a `TextCursor` literal adds `history: EditHistory::default()`.
- `TextInput` paints the caret its own `TextInputState` walked to, not the
  descriptor's `cursor_line`/`cursor_col` (#2978 TE11), so a host that
  never echoes a caret back still sees it where typing lands.
  `TextInputPrimitiveLayout` gains `line_height`, `units` and `relayout`.
- `"text_input"` (`TextInput`) and `"text_field"` (`TextField`) join the
  static `widget_kinds!` table.
- `quadraui-binding-core`: `"text_input"`, `"text_field"`, `"password"` and
  `"textarea"` are generic `LeafDescriptor::Widget` leaves decoded through
  `widget_kinds!` and edited through the core widgets' own `Interactive`
  state; their `ExtraPaint` impls, the binding-side `PasswordInput`/
  `TextArea` wrappers, `extra_as_text_input` and `text_input.rs`
  (`TextEditorCache`, `text_input_key_event`, `text_input_insert_event`,
  `text_input_click_event`, `apply_text_input_edit`, `clamp_cursor`) are
  deleted, along with `InteractionEngine::sync_text_input_carets`.
  `InteractionEngine::paint_with_widget_state(paint)` installs the
  engine's per-widget state for a paint pass, so every generic leaf paints
  from the state its own input handling walked; that state is keyed by the
  widget's own id (else the leaf id). A dialog's or popover's layout
  subtree routes keys and committed text to a focused generic leaf
  through the same dispatch.
- The `"menu_bar"` wire kind decodes to `AppMenu`, the whole application
  menu with its dropdown cascade as popups, instead of the bare `MenuBar`
  strip (#2977, 0.12 rec 12). `AppMenu` and `MenuDef` derive `JsonSchema`
  under the `schema` feature. An `AppMenu` whose `view` is the default is
  uncontrolled: it keeps the view it moves to in the new
  `AppMenuState::view` and paints, opens its popups and handles input
  from it, so a host that never applies `AppMenuEvent::Changed` still has
  a working menu. A host that applies it controls the view as before.
- Binding-core delivers a key a focused generic leaf answers `Ignored`
  after emitting its own report of it (a tab bar's scoped `KeyPressed`)
  once, as that report, and not also as the raw `KeyPressed`.
- `Form`'s widget contract reads its live state (#2977): its layout and
  paint apply the stored `FormState`'s scroll offset, caret and field
  focus, so a wheel notch or a scroll-into-view moves what is painted and
  hit-tested; a host reporting the form focused through
  `PaintState::focus_ring_visible` shows its focused-row highlight. Its
  `Interactive::handle` requests focus for the newly focused field's stop
  (`FocusSpec::Children`'s sub-target) whenever field focus moves, so a
  host knows which child holds focus; moves field focus on a plain Up/Down
  the focused field has no use for, stopping at either end; and captures
  the pointer for a slider drag. `FormDialog`'s Tab hand-off reads the
  form's live field focus, so it follows focus the form tracks itself.
- `TabBar`'s keyboard navigation starts from the descriptor's
  `chrome.focused_index` while its `TabBarState` names no tab (#2977), so
  a host that threads keyboard focus through the descriptor keeps its
  place: Right moves on from that tab and Enter activates it.
