- `compose::MenuSystem::render` now installs a native macOS menu bar
  (#2560) with each top-level item's real dropdown content instead of an
  empty submenu: `MenuSystem::build_menu_bar` previously zeroed out
  `MenuBarItem::submenu` on every call, so the per-frame repaint pass
  that follows the initial paint overwrote `Backend::install_menu_bar`'s
  correctly-populated `NSMenu` with one whose top-level items had no
  dropdown at all, regardless of where the `menu_bar` descriptor sat in
  the render tree. TUI/GTK's painted strip was unaffected (their dropdown
  overlay never read this field), but `A11yPrimitive for MenuBar`'s
  accessible children were silently empty too.
