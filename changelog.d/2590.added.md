- New standalone `TextField` primitive (#2590): a single-line framed text field
  with an optional leading `Icon` (e.g. a search magnifier) and an
  optional clear (×) button, placeable anywhere rather than only as a
  `Form` row (now a `Surface::TextField`/`FrameZone::TextField` zone
  too, so it can sit in a `ScreenLayout` like any other primitive).
  `TextField::layout` scrolls horizontally so the cursor always stays
  visible, and drops the clear button first, then the icon, under
  width pressure. Editing goes through the existing `EditOp`/
  `TextEditor` machinery via the new
  `primitives::text_input::apply_flat_edit_op` bridge, now shared with
  `FormController`'s `FieldKind::TextInput`/`TextArea`/`PasswordInput`
  handling. `Backend::draw_text_field` is required on every backend:
  TUI paints the one-row `[ icon value × ]` rasteriser; GTK/macOS/Win
  share a stroked-box painter built from the same text-run/caret/
  selection routine `Form`'s own `TextInput` row paints with. Exposed
  to Python/JS as the `"text_field"` additive primitive kind.
