- `HelpOverlay` carries the open/close state machine itself (#2957):
  `HelpOverlay::handle_event` resolves a `UiEvent` (keys through
  `handle_key`, now public; any other event is consumed while open and
  ignored while closed), `HelpOverlay::apply` writes a reported
  `HelpOverlayAction` back onto `open`, and `HelpOverlay::toggle_action`
  names the flip. `compose::HelpOverlayController` and the deprecated
  `HelpOverlayEvent` are removed: hold a `HelpOverlay`, set its `help`
  per frame and paint it with `draw_dyn`.
- `TreeViewState`'s multi-selection is a `SelectionCore` (#2957): the
  `anchor`/`selected` fields become one `selection` field, so a tree grows
  a Ctrl/Cmd or Shift selection through the same core `DataTableState`
  uses.
- On TUI a `Canvas` `DrawOp::Rect` whose edges all sit on cell boundaries
  paints solid cells instead of braille dots (#2957): an opaque colour
  blanks each cell to that colour and covers shapes declared before it,
  and a translucent colour blends over each cell's background while
  keeping the glyph and foreground already there, so a scrim dims the
  content under it. `CellSurface::tint_bg` is the cell-grid form of that
  translucent fill. Any other `Rect` still paints braille.
- The shared pixel `MessageList` painter sizes a styled row's glyphs by
  its `MessageRow::scale` (markdown headings) through
  `PaintSurface::surface_draw_text_line`, on GTK, macOS and Windows alike
  (#2957). An underlined span on a scaled row paints without its
  underline.
