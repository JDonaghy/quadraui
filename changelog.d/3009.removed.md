- `quadraui_binding_core::layout::LeafDescriptor::Button`,
  `quadraui_binding_core::hit::PaintedHit::Button`,
  `quadraui_binding_core::hit::HitDetail::ButtonBody`, and the fixed `button`
  field on `RenderFrame`/`RenderRefs`/`BindingHost` are removed (#3009):
  `Button` already decodes through the generic
  `crate::extra_paint::WIDGET_KINDS` seam (`LeafDescriptor::Widget`,
  `PaintedHit::Widget`, `HitDetail::WidgetBody`) `IconGrid`/`CellGrid`/
  `Switch`/`RadioGroup` already use, so the dedicated fixed-slot machinery
  is now dead weight. `BindingHost` carries its `"button"` slot as an entry
  in the new `BindingHost::widgets` map instead of a typed field (`SLOT_BUTTON`
  is unchanged, still `0`, for ABI compatibility with `quadraui-ffi`'s
  `qui_button_insert`/`QUI_SLOT_BUTTON`). A `Button` click or Enter/Space key
  now emits `UiEvent::ButtonActivated` through the generic dyn-widget
  dispatch instead of `UiEvent::Form(.., FormEvent::ButtonClicked)` via the
  removed `crate::semantic::button_clicked_event`. The wire shape is
  unaffected for a binding author: a `"button"` key still decodes the exact
  same `ButtonDescriptor` in both the `LayoutLeafNode` and `RenderFrameDict`
  shapes (`wire.pyi`/`wire.d.ts`/`docs/bindings-wire-format.md` regenerated).
  A handler reading the raw event stream sees that activation where it used
  to see a hit-tested `MouseDown` plus a `Form`-wrapped twin, and the
  `quadraui-py`/`quadraui-node` app layers dispatch `Button`'s
  `on_click`/`onClick` from it. None of the removed Rust types had a caller
  in any published consumer. The flat-slot paint order moves too: a
  `"button"` slot used to paint first among the fixed bands and now paints
  last, after every other fixed slot and `EXTRA_PRIMITIVE_KINDS` entry — a
  host filling `qui_button_insert` plus another slot sees a different
  on-screen stacking order.
